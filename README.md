# lhdsuite

Real-design correctness tests and benchmarks for LiveHD: compilation,
synthesis, simulation, logical equivalence checking (LEC), and formal
verification. The scripts in `bench/` also serve as examples of each flow.

## Source trees

Designs use three source directories:

| Directory | Purpose |
| --- | --- |
| `verilog/` | Original RTL, either written in Verilog/SystemVerilog or generated from Chisel. This is the reference design. |
| `pyrope/` | Pyrope automatically generated by LiveHD from the reference RTL. This preserves the translator's output as a baseline. |
| `pyrope2/` | An agent-evolved version of `pyrope/`, rewritten for clarity and idiomatic Pyrope. |

**In `pyrope2/`, anything internal may change as long as top-level module
compatibility is preserved.** Agents may rename or replace internal modules,
redesign their interfaces, reorganize files and hierarchy, and change data
representations or implementation structure. Preserve the public top-level
module name, ports, supported configuration, and externally observable
behavior, including cycle timing and reset behavior. Check equivalence against
the reference RTL; a bounded pass or an inconclusive result is not an unbounded
proof.

Generation is automatic, but refreshing the checked-in `pyrope/` baseline is
an explicit maintenance step. Benchmark runs use scratch directories and do
not rewrite it. Keep agent cleanup in `pyrope2/`; the files selected by each
core's `BUILD` determine which version a benchmark consumes.

Except for `pyrope2/` and the `match*` tests, Pyrope design sources are generated.
When generated code is wrong, fix the generation defect and refresh the
affected files in `pyrope/`, checking them against the reference RTL.

The tests in verif, should run with both `pyrope/` and `pyrope2/`

## Designs

| Design | Scope |
| --- | --- |
| `dino` | Dual-issue RISC-V CPU, top `PipelinedDualIssueCPU`. |
| `minion` | Multithreaded RISC-V core with vector/tensor units, top `minion_top`. |
| `cva6` | Whole OpenHW CVA6 core in Pyrope, top `cva6`. |
| `picorv32` | YosysHQ PicoRV32 under the parameter-pinning `picorv32_top` wrapper. |
| `matched_filter` | Configurable streaming matched filter, 64 taps by default. |
| `xs_*` | XiangShan blocks sharing `xiangshan/Backend/`: ALU, ROB, rename table, divider, execution block, and backend. |

CVA6's local `verilog/` contains only a cache tag-comparator cone. Its
benchmarks use the whole Pyrope core and omit Verilog and cross-language LEC
scenarios. Formal checks target the integer ALU. See the
[CVA6 generation recipe](cva6/README) for the full-core source.

## Setup

Install [Bazelisk](https://github.com/bazelbuild/bazelisk); `.bazelversion`
selects Bazel. LiveHD and its C++ dependencies are built from source.
[MODULE.bazel](MODULE.bazel) currently selects the sibling `../livehd`
checkout. To select another checkout, pass `--override_module=livehd=/path/to/livehd`.
Builds default to `-c opt`; use `-c dbg` for compiler debugging.

Synthesis requires sky130 installed and enabled through
[ciel](https://github.com/fossi-foundation/ciel):

```bash
pip install ciel
ciel ls-remote --pdk-family sky130
ciel enable --pdk-family sky130 <version>
```

The harness requires the newest installed sky130 version to be enabled and
records its hash. It resolves the Liberty directory through `ciel`, replacing
any inherited `HAGENT_TECH_DIR`; ambiguous or mismatched versions fail with a
diagnostic.

Verilator is optional. Install it for the comparison scenarios; set
`VERILATOR` to override discovery. These scenarios skip when it is absent.

## Running

```bash
bazel test //bench:dino_compile_verilog --test_output=all  # one scenario
bazel test //bench:dino                                  # one core
bazel test //...                                         # all tests; can take hours
bazel run //bench:show                                   # last recorded results
bazel run //bench:show -- --core minion --no-cmds          # compact, one core
```

Targets follow `//bench:<core>_<scenario>`. Available scenarios depend on the
core's sources and drivers; [bench/defs.bzl](bench/defs.bzl) is authoritative.
Tests carry `core_<name>` tags and run exclusively to keep timings isolated.
Run one synthesis job at a time.

| Scenario | Checks or measures |
| --- | --- |
| `compile_verilog`, `compile_pyrope` | Front-end compilation and throughput. |
| `compile_pyrope_parallel` | Separate compilation through an import-aware generated Makefile. |
| `compile_incremental` | Compilation across cold, comment-only, and semantic edits. |
| `synth`, `synth_incremental` | Mapping time, reuse, gate count, area, and timing with sky130. Minion also runs a flat-mapping comparison. |
| `synth_lec_synth`, `synth_lec_flat` | Synthesized netlist equivalence, including reuse after a comment edit; flat is Minion-only. |
| `sim_verilog`, `sim_pyrope`, `sim_verilator` | Simulation with checked output values; host compilation and execution are timed separately. |
| `sim_incremental`, `sim_incremental_llvm` | Simulator build reuse across edits, using C++ or LLVM; these scenarios do not execute the driver. |
| `lec`, `lec_bug`, `lec_incremental` | Cross-language equivalence, injected-bug detection, and proof-cache reuse. |
| `verify`, `verify_bug`, `verify_temporal`, `verify_incremental` | Formal sidecar properties, mutant refutation, sequential properties, and reuse where supported. |

Logs contain exact `CMD` lines and `METRIC <name> <value> <unit>` records.
`//bench:show` summarizes existing logs; run tests first. Detailed step logs
and `metrics.jsonl` are under
`bazel-testlogs/bench/<target>/test.outputs/`. Add
`--test_env=BENCH_VERBOSE=1` to include full step logs in test output.

Translation checks in [verif/](verif/BUILD) regenerate into scratch space:

```bash
bazel test //verif:genprp_dino  # Verilog -> Pyrope, then LEC against the original
bazel test //verif:v2v_dino     # Verilog -> Pyrope -> Verilog, then LEC
```

These correctness tests also run under `//...`.

## Incremental checks

Incremental flows share a work directory across a cold run, an unchanged or
comment-only run, and a semantic edit. Some flows add a separate warm pass.
`tests/comment1/` contains comment-only overlays; `tests/bug1/` contains
intentional bugs that LEC or formal verification must detect.

Measure reuse by saved work and elapsed time, not cache-hit counts alone.
Simulation output assertions and strict proof gates remain enabled.

## Known-failing scenarios

These are previously reported failures, not a fresh status report for the
selected LiveHD checkout. Re-run the relevant target to establish its status.

| Targets | Previously reported limitation |
| --- | --- |
| `//bench:picorv32_sim_verilog`, `picorv32_sim_pyrope` | Missing program store; architectural readback fails. |
| `//bench:picorv32_lec`, `picorv32_lec_bug` | A six-cycle bounded result misses behavior beyond reset and cannot establish equivalence or detect the mutant. |
| `//bench:cva6_sim_pyrope` | Generated icache prevents the whole-core program from retiring instructions. |
| `//bench:minion_lec`, `minion_lec_incremental`, `minion_synth_lec_synth` | Unresolved state, memory, and hierarchical proof obligations. |
| `//verif:genprp_minion` | Slang driver-order failure during generation. |
| `//verif:genprp_xs_enqentry_4` | Excessive front-end memory use. |
| `//verif:genprp_xs_tracebuffer` | Combinational cycle in generated Pyrope. |

Keep these checks live. Fix compiler defects in LiveHD; fix harness defects
in the suite. Preserve the expected simulation data and proof requirements.
CVA6 must execute the whole-core program before that gate passes.

## Adding or maintaining a core

A core's `BUILD` exposes `verilog`, `verilog_filelist`, `pyrope`, `pyrope_top`,
`sim`, `verif`, and `tests` filegroups. Add its configuration to `CORES` in
[bench/defs.bzl](bench/defs.bzl) and instantiate `core_benches` in
[bench/BUILD](bench/BUILD).

The configuration names the top, verification unit, source flags, simulation
drivers, and supported scenarios. The verification unit and injected edits
must be reachable from the selected top. Shared scripts read the `CORE_*`
contract in [bench/common.sh](bench/common.sh); keep design-specific settings
in `CORES`. See [AGENTS.md](AGENTS.md) for maintenance conventions.
